# 库存同步规则 · 产品需求文档

**版本** v1.0　**日期** 2026-10　**状态** 已实现原型

---

## 一、背景与目标

### 1.1 背景

OMS 需要将 WMS 中的商品库存数据同步推送到各销售渠道（EDI 零售商、电商平台、文件传输等）。不同渠道、不同货主、不同商品的同步策略差异大，现有方式依赖人工维护脚本，无法灵活配置，且缺乏跨渠道分配约束。

### 1.2 目标

- 提供可视化配置界面，支持按规则管理多渠道库存同步策略
- 支持全局计算方式与 SKU 级差异化覆盖
- 支持跨规则分配约束，防止同一 SKU 库存被超额分配
- 支持批量操作，提升运营效率

---

## 二、名词定义

| 术语 | 说明 |
|---|---|
| 同步规则 | 描述"什么库存、用什么方式计算、同步到哪里、何时同步"的配置单元 |
| 按照设置同步 | 直接按配置比例或固定数量输出库存值 |
| 扣减后同步 | 从实际库存中扣除指定缓冲量后输出剩余量 |
| 差异化配置 | 针对特定 SKU 设置独立于全局规则的计算方式 |
| 分配比例 | 本规则在该渠道分得的库存池百分比 |
| 预估余量 | 该 SKU 在其他规则已占用后，本规则可用的最大分配比例（= 100% − 其他规则已占用 %） |
| 跨规则分配约束 | 同一 SKU 在所有规则中的分配比例之和不超过 100% |

## 三、功能结构

```
库存同步规则
├── 基本信息
├── 同步目标
├── 同步范围（货主 + 仓库）
├── SKU 与计算规则
│   ├── 计算方式

│   │   │   └── 启用跨规则分配总量约束（仅百分比模式）

│   ├── SKU 范围
│   │   ├── 全部 SKU（动态）
│   │   ├── 仅同步指定 SKU（静态列表）
│   │   └── 排除指定 SKU
│   └── SKU 差异化配置

├── 执行频率
└── 异常处理
```

## 四、详细需求

### 4.1 基本信息

| 字段 | 说明 | 规则 |
|---|---|---|
| 规则名称 | 必填，支持模板建议列表 | 最大长度 100 字符 |
| 启用状态 | 启用 / 停用 / 草稿 | 默认启用 |
| 优先级 | 数字，数值越高越优先 | 默认 50 |

---

### 4.2 同步目标

**目标渠道**（必填）
- 支持多选，渠道类型：EDI、平台授权、文件传输
- 渠道状态显示：已启用 / 测试中 / 已暂停

**Retailer 标识**（EDI 渠道必填）
- EDI 报文中对方的 retailer 标识，如 `WALMART_US`
- 支持预设选项 + 自定义输入

**目标仓库**（平台授权渠道可选）
- 选择将库存推送到平台侧的哪个 Location
- 支持预设仓库列表 + 手动输入 Location Code

---

### 4.3 同步范围

**货主**
- 全部货主 / 指定货主 / 排除货主
- 支持多标签输入，提供预设货主列表

**仓库**
- 全部仓库 / 指定仓库
- 指定时支持多选 + 选择合并策略（各仓求和 / 取最大值）

---

### 4.4 SKU 与计算规则

#### 4.4.1 计算方式

**模式一：按照设置同步**

| 子类型 | 说明 | 公式 |
|---|---|---|
| 百分比 | 同步 X% 的实际可用库存 | `同步量 = 实际库存 × X%` |
| 固定数量 | 始终同步固定 N 件，不随库存波动 | `同步量 = N` |

**模式二：扣减后同步**

| 子类型 | 说明 | 公式 |
|---|---|---|
| 百分比 | 扣除 X% 作为缓冲，同步剩余 | `同步量 = 实际库存 × (1 - X%)` |
| 固定数量 | 扣除 N 件后同步剩余 | `同步量 = 实际库存 - N - 其他扣减项` |

**扣减后同步的附加扣减项**（可多选）
- 扣减 Open Order：已下单但未发货的订单占用量
- 扣减安全库存：填写具体件数
- 加入在途库存：将在途量计入可同步库存
- 额外保留量：扣减完成后再额外扣除

**约束逻辑**

| 条件 | 约束 |
|---|---|
| 按照设置同步 + 百分比 | 可启用跨规则分配总量约束 |
| 按照设置同步 + 固定数量 | 不支持分配约束（隐藏开关） |
| 扣减后同步（任意子类型） | 不支持分配约束（隐藏开关） |
| 从不支持模式切换到支持模式 | 不自动恢复约束开关 |
| 从支持模式切换到不支持模式 | 自动关闭约束开关 |

#### 4.4.2 跨规则分配总量约束

**启用条件**：计算方式 = 按照设置同步 + 百分比

**启用后效果**：
1. SKU 范围列表切换为分配模式（分配比例列替换计算规则列）
2. 实时显示各 SKU 的预估余量（100% − 其他规则已占用）
3. 全局比例填写后，实时检测与其他规则的冲突
4. 超出行整行红色高亮，分配比例输入框红色边框
5. 保存时若存在**配置阶段可检测到的**超出 SKU，阻止保存并显示错误提示

**全局比例冲突检测（配置阶段）**：
- 对所有未配置差异化分配的 SKU，以全局比例为生效值
- 若 `全局比例 + 其他规则已占用 > 100%`，展示警告
- 警告列出冲突 SKU 编码，提示在差异化配置中单独设置

**运行时约束超出处理策略（必选）**：

配置阶段无法预知的超出场景：
- WMS 在规则保存后新增了商品，该商品在其他规则中已有分配，全局比例加起来超出
- 其他规则被修改导致本规则某 SKU 的可用余量减少
- SKU 范围为"全部 SKU"时，新 SKU 按全局比例同步时恰好超出

因此启用约束时，需要配置运行时超出的处理方式：

| 策略 | 行为 | 适用场景 |
|---|---|---|
| 按可用余量同步 | 自动将同步比例降至 `预估余量`（如余量 30% 则同步 30%） | 默认推荐，安全不丢数据 |
| 跳过该 SKU | 本次同步跳过该 SKU，不推送任何数据 | 对超出零容忍，宁可不同步 |
| 强制同步并告警 | 按配置比例强制同步，同时触发告警通知运营团队 | 告警驱动人工处理，允许短暂超额 |

> 注：无论选择哪种策略，所有运行时超出事件均写入同步日志，可在运营监控中查看。

#### ⚠️ 架构说明：分配约束的正确实现方式

当前原型将分配比例配置在每条规则内，**这是一个简化模型，存在根本性问题**：

**问题场景**：规则 A、B、C 均为"全部 SKU + 按可用余量同步"，WMS 新增 SKU-X：
- 规则 A 执行时：SKU-X 在分配账本中尚无记录 → 其他规则占用 0% → A 自行占用 40%
- 规则 B 执行时：同上 → B 自行占用 40%
- 规则 C 执行时：同上 → C 自行占用 40%
- 合计：120% > 100%，约束完全失效

**根本原因**：各规则独立查询时没有实时共享状态，彼此不知道对方已经占用了多少。

**正确的系统架构**应分为两层：

**第一层：库存分配账本（独立模块）**

```
SKU-A001  →  Walmart: 40%  |  Target: 30%  |  Shopify: 30%
SKU-B002  →  Walmart: 50%  |  Target: 50%
SKU-X（新增）→  未分配，状态：待运营配置
```

- 这是所有规则共享的唯一真相
- 运营在"库存分配管理"页面统一维护，不属于任何单条规则
- 系统在此校验所有渠道的比例之和 ≤ 100%

**第二层：同步规则（引用账本）**

- 规则只负责：哪些 SKU、用什么计算方式、推送到哪里、何时推
- 分配比例从账本中读取，规则本身不存储
- 规则表单中"分配比例"字段改为只读展示，跳转到账本页面配置

**新增 SKU 的处理流程（自动归一化）**：

```
WMS 新增 SKU-X
  ↓
系统收集所有覆盖 SKU-X 的规则及其全局比例
  例：规则 A=40% / 规则 B=40% / 规则 C=40%，合计 120%
  ↓
计算比例之和
  ├─ 之和 ≤ 100%：直接按各自比例同步，无需干预
  └─ 之和 > 100%：按比例归一化自动分配
      归一化：A=33.3% / B=33.3% / C=33.3% → 合计 100%
  ↓
按归一化比例执行同步，写入告警日志
  ↓
告警运营："SKU-X 已自动分配，建议在账本中确认比例是否符合业务预期"
  ↓
运营在账本中手动调整后，下次同步按调整后的比例执行
```

**自动归一化的适用条件与局限**：

| 场景 | 结果 | 是否合适 |
|---|---|---|
| A=40% B=30% C=30%，合计 100% | 无需处理，直接同步 | ✅ |
| A=40% B=40% C=40%，合计 120% | 归一化为各 33.3% | ⚠️ 比例关系对，绝对值偏低 |
| A=80% B=80% C=80%，合计 240% | 归一化为各 33.3% | ❌ 完全不符合预期，须人工确认 |

> 归一化保证不超额，但无法保证符合业务预期。自动分配后**必须告警**，让运营确认或在账本中手动修正。长期依赖归一化而不维护账本，会导致各渠道分配比例持续漂移。

> **当前原型状态**：上述账本架构尚未实现，原型使用静态 Mock 数据（`MOCK_SKU_ALLOCATIONS`）模拟其他规则的已占用比例，仅用于演示交互逻辑，不代表最终实现方式。

#### 4.4.3 SKU 范围

**全部 SKU（动态）**
- 规则不绑定具体 SKU 列表
- 每次同步时实时从 WMS 拉取当前全量 SKU
- WMS 新增商品在下次同步自动纳入，遵循整体计算规则
- 无需手动更新规则

**仅同步指定 SKU**
- 静态 SKU 列表，只同步列表内的 SKU
- 添加方式：单个搜索、批量搜索（粘贴多个编码）、文件导入（Excel / CSV）
- SKU 列表展示：编码 + 计算规则 + 值（或分配比例）
- WMS 新增商品不自动纳入，需手动添加

**排除指定 SKU**
- 排除列表内的 SKU，其余全部同步（等同于动态）
- WMS 新增商品自动纳入（除非在排除列表中）

#### 4.4.4 SKU 差异化配置

**触发条件**：SKU 差异化配置开关开启

**开启行为**：自动加载当前 SKU 范围内全部 SKU 到配置列表（已有配置保留，仅补充缺失项）

**两种模式**

| 模式 | 触发 | 可配置项 | 表格列 |
|---|---|---|---|
| 分配模式 | allocationConstraint = ON | 分配比例（% 仅） | SKU 编码 \| 预估余量 \| 分配比例 |
| 计算覆盖模式 | allocationConstraint = OFF | 整体规则 / 同步比例 / 固定数量 / 扣减数量 | SKU 编码 \| 计算方式 \| 值 |

**预估余量说明**
- 计算公式：`预估余量 = 100% − 其他规则对该 SKU 已占用的分配 %`
- 始终显示，不依赖本规则是否已填分配比例
- 颜色：`> 10%` 绿色 / `1–10%` 橙色 / `≤ 0%` 红色
- 当全局比例 > 预估余量时，行整体红色高亮（即使分配比例未填）

**整体规则的值显示**
- 计算方式选"整体规则"时，值列显示继承的全局值（灰色只读）
- 按照设置同步 + 比例 80% → 显示 `80%`
- 按照设置同步 + 固定 500件 → 显示 `500 件`
- 扣减后同步 + 比例 20% → 显示 `扣减 20%`
- 扣减后同步 + 固定 300件 → 显示 `扣减 300 件`

**批量操作**
- 每行有复选框，点击行任意位置（除交互控件）可切换选中
- 列头有全选/反选复选框（仅针对当前过滤结果）
- 选中行后出现批量操作栏：
  - 分配模式：批量填写分配比例
  - 计算覆盖模式：批量选择计算规则 + 填写值
- 搜索 + 全选搜索结果 + 批量应用：三步完成批量配置

### 4.5 输出字段

以下 7 个开关控制同步报文的输出内容：

| 开关名称 | 英文名 | 默认值 | 说明 |
|---|---|---|---|
| 同步 SKU 状态 | Sync SKU Status | 开 | 随库存数量一并输出 SKU 可用 / 不可用状态 |
| 不可用 SKU 置零 | Zero Out Unavailable SKUs | 开 | SKU 状态不可用时，同步库存强制输出为 0 |
| 可用 SKU 无流水时置零 | Zero Out SKUs with No Ledger Records | 关 | SKU 状态可用但无任何库存流水记录时，输出为 0 |
| 忽略已发货时间限制 | Ignore Fulfillment Window Restriction | 关 | 启用后 WMS 返回库存记录，无论发货时间窗口如何 |
| 同步零库存 SKU | Include Zero-Inventory SKUs | 开 | 库存为 0 的 SKU 仍然输出，不跳过 |
| 同步 Retailer SKU 名称 | Sync Retailer SKU Name | 关 | 随库存报文附带 Retailer 侧的 SKU 名称 |
| 包含条码 | Include Barcode | 关 | 输出 UPC、EAN 等条码字段 |

### 4.6 执行频率

| 模式 | 说明 |
|---|---|
| 每日定时 | 每天在指定时刻执行，可添加多个时间点 |
| 按时间间隔 | 按固定间隔循环执行（30分钟 ~ 24小时） |
| 实时触发 | 库存发生特定变化时立即推送（库存归零、SKU 状态变更、库存超阈值、入库完成） |
| 指定日期时间 | 在一个或多个固定日期时刻各触发一次，适用于大促、节假日 |
| 拉取模式 | Retailer 主动拉取，系统不主动推送，无需配置推送地址 |

**推送目标 URL**：非拉取模式时必填，系统以 HTTP POST 方式推送库存报文

### 4.7 异常处理

| 配置项 | 说明 | 默认值 |
|---|---|---|
| 失败重试次数 | 推送失败时自动重试的最大次数 | 3 次 |
| 重试间隔 | 每次重试之间的等待时间（分钟） | 5 分钟 |
| 重试耗尽后处理 | 告警并挂起 / 告警并跳过 / 静默跳过 | 告警并挂起 |

## 五、交互规则汇总

### 5.1 约束模式切换联动

```
用户开启约束
  → 计算方式锁定为"按照设置同步 + 百分比"
  → SKU 差异化配置仅显示"分配比例"列
  → 差异化配置不再允许"固定数量"/"扣减数量"选项

用户切换计算方式到"固定数量"
  → 自动关闭约束开关

用户切换计算方式到"扣减后同步"（任意子类型）
  → 自动关闭约束开关
```

### 5.2 全局比例冲突检测（约束模式）

```
条件：allocationConstraint = ON AND ratio 已填写
对所有 SKU 执行：
  effectiveRatio = 该 SKU 差异化分配比例（若未填则使用全局 ratio）
  if effectiveRatio + 其他规则已占用 > 100
    → 该 SKU 记入冲突列表
if 冲突列表非空
  → 展示警告横幅，列出冲突 SKU 编码
  → 相关行整行红色高亮
  → 保存时阻止提交
```

### 5.3 预估余量计算

```
预估余量 = 100 - 其他规则对该 SKU 的分配 %
（与本规则是否填写分配比例无关）

颜色：
  > 10%  → 绿色
  1-10%  → 橙色
  ≤ 0%   → 红色

allocOver 条件（整行红色高亮）：
  effectiveRatio = 本规则分配比例（未填则用全局）
  allocOver = effectiveRatio > 预估余量
```

### 5.4 整行选中交互

- 点击行任意区域（除 select / input / button）切换该行选中状态
- 选中后行背景变为主色调浅背景
- allocOver 行保持红色背景，优先级高于选中蓝色

## 六、数据模型（核心字段）

```typescript
type SyncRule = {
  // 基本信息
  name: string
  status: 'active' | 'inactive' | 'draft'
  priority: number

  // 同步目标
  channelIds: string[]
  retailerInput: string
  platformTargetLocation: { mode: 'preset' | 'custom'; presetId: string; customCode: string }

  // 同步范围
  ownerMode: 'all' | 'include' | 'exclude'
  ownerInput: string
  warehouseMode: 'all' | 'specific'
  warehouseIds: string[]
  warehouseMerge: 'sum' | 'max'

  // SKU 范围
  skuMode: 'all' | 'include' | 'exclude'
  skuBy: 'sku_list' | 'tag' | 'category'
  skuList: string        // 逗号分隔的 SKU 编码

  // 计算方式
  qtyMode: 'configured' | 'deduct'
  syncValueType: 'ratio' | 'fixed'
  ratio: string          // 百分比值（0-100）
  fixedQty: string       // 固定件数
  deductOpenOrder: boolean
  deductSafety: boolean
  safetyQty: string
  reserveQty: string
  inclInTransit: boolean

  // 分配约束
  allocationConstraint: boolean  // 仅 configured + ratio 模式可开

  // SKU 差异化配置
  skuLevelOverrideEnabled: boolean
  skuLevelConfigs: {
    skuCode: string
    overrideType: '' | 'ratio' | 'fixed' | 'deduct'  // '' = 整体规则
    value: string
    allocationRatio: string  // 分配模式下使用
  }[]

  // 输出字段
  syncStatus: boolean
  unavailToZero: boolean
  noLedgerAsZero: boolean
  ignoreShipTimeLimit: boolean
  includeZero: boolean
  syncRetailerSkuName: boolean
  includeBarcode: boolean

  // 执行
  frequency: 'daily' | 'interval' | 'realtime' | 'scheduled' | 'pull'
  execTimes: string[]
  intervalMinutes: string
  pushUrl: string
  realtimeEvents: string[]
  scheduledDatetimes: string[]

  // 异常处理
  retryMax: string
  retryInterval: string
  onFailure: 'alert_wait' | 'alert_skip' | 'silent_skip'
}
```

## 七、边界条件与限制

| 场景 | 处理方式 |
|---|---|
| 全部 SKU 模式 + 新增 WMS 商品 | 下次同步自动纳入，差异化配置中有单独设置的 SKU 仍用独立规则 |
| 分配比例之和超过 100% | 保存时阻止，展示冲突 SKU 列表 |
| 固定数量模式 + 分配约束 | 不兼容，切换固定数量时自动关闭约束 |
| 跨规则固定数量与百分比混用 | 固定数量规则不计入百分比池，两套逻辑独立 |
| 推送 URL 未填 + 非拉取模式 | 保存时阻止，聚焦到 URL 输入框 |
| EDI 渠道未填 Retailer | 保存时阻止，聚焦到 Retailer 输入框 |

## 八、未来迭代方向

1. **库存分配账本（优先级：高）**：将分配比例从规则中剥离，建立独立的"库存分配管理"模块。账本是各规则共享的单一真相，规则只读取账本，不存储分配比例。这是分配约束正确运作的前提。
2. **新 SKU 待分配通知**：WMS 新增商品后，自动检测是否在分配账本中已配置，未配置的 SKU 暂停同步并推送告警，运营配置后自动生效。
3. **实时跨规则数据**：当前预估余量基于 Mock 数据，正式版需从账本 API 实时获取各 SKU 在其他规则中的已占用分配比例。
4. **批量获取库存**：当前"获取当前库存"模拟 API，正式版需对接 WMS 实时库存接口。
5. **规则测试执行**：在配置页支持"沙箱同步"，预览本规则对指定 SKU 的计算结果。
6. **分配冲突可视化**：在规则列表页展示跨规则分配冲突的总览视图。
7. **租户级约束配置**：支持将分配约束模式作为租户级默认配置，避免每条规则重复设置。
