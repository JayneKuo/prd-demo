# 分仓规则引擎设计方案

## 一、核心模型

### 引擎本质

分仓引擎是一个 **两轮执行的约束求解器**：

```
第一轮：所有规则当硬约束 → 严格执行 → 找到合法仓 → 结束
第二轮：去掉软约束 → 放宽条件再跑一遍 → 找到次优仓 → 结束
两轮都不满足 → 进入兜底策略
```

借鉴 Dynamics 365 DOM 的设计：每条规则可标记为「硬约束」或「软约束」。

### 用户创建的"规则"是什么

用户创建的一条分仓规则 = **条件 + 引擎参数组**

含义是："当订单满足这些条件时，引擎按这组参数来跑分仓"

多条规则按优先级排列，订单命中第一条匹配的规则后，使用该规则的参数组执行分仓。
所有规则都不命中 → 使用系统默认参数组。

## 二、引擎参数组（一条规则要配的内容）

### 2.1 仓库排序

| 参数 | 选项 | 说明 |
|------|------|------|
| 排序方式 | 距离优先 / 仓库优先级 / 库存深度 | 候选仓的初始排序 |
| 距离计算 | 配送时效 / 直线距离 | 仅距离优先时有效 |
| 库存维度 | 绝对量 / 满足率 | 仅库存深度时有效 |

### 2.2 仓库约束（可标记硬/软）

| 约束 | 类型 | 说明 |
|------|------|------|
| 校验商品信息 | 硬约束 | 仓库必须有该SKU的商品档案 |
| 校验库存 | 硬→软 | 仓库该SKU可用库存≥需求量 |
| 危险品必须专仓 | 硬约束 | 含危品SKU只能分配到有资质仓 |
| 大件必须大件仓 | 硬约束 | 大件SKU只能进大件仓 |
| 效期商品专仓 | 硬约束 | 效期品只能进冷链/效期仓 |
| 临期禁止出库 | 硬约束 | 剩余效期≤阈值天的批次不可分配 |
| 不允许混批 | 软约束 | 同商品发货必须同一批次 |

### 2.3 分仓策略

| 参数 | 选项 | 说明 |
|------|------|------|
| 允许多仓履约 | 是/否 | 不同商品能否分到不同仓 |
| 允许同一商品多仓履约 | 是/否 | 同SKU大数量能否拆给多仓 |
| 优先整单同仓 | 是/否 | 有单仓满足时是否优先选它 |
| 允许部分下发 | 是/否 | 部分商品能分仓而部分不能时，能发的先发吗 |

### 2.4 出库拆分

| 参数 | 选项 | 说明 |
|------|------|------|
| 一单一商品 | 是/否 | 同仓多SKU是否拆成多张出库单 |
| 样品不能单独出库 | 是/否 | 样品必须跟随主品 |
| 危险品独立出库 | 是/否 | 危品不和普通品同一出库单 |
| 大件独立出库 | 是/否 | 大件单独一张出库单 |
| 最大出库单数 | 数字 | 超出时合并 |

### 2.5 兜底策略

| 参数 | 选项 | 说明 |
|------|------|------|
| 兜底动作 | 挂起 / 通知人工 / 按优先级强推 / 取消 | 两轮都不满足时 |
| 挂起超时 | 小时数 | 超时后转人工 |
| 通知角色 | 运营/仓库主管/采购 | 通知谁 |

## 三、引擎执行流程

```
订单进入
    │
    ▼
匹配规则（按优先级，命中第一条）
    │
    ▼ 获取该规则的参数组
    │
┌───────────────────────────────────────────────┐
│ 第一轮（全约束）                                │
│                                               │
│ 1. 列出所有候选仓                              │
│ 2. 按仓库约束过滤（全部当硬约束）               │
│    - 无商品信息 → 排除                         │
│    - 无库存 → 排除                             │
│    - 危品无资质 → 排除                         │
│    - 大件非大件仓 → 排除                       │
│    - 效期品非效期仓 → 排除                     │
│    - 临期批次 → 排除该批次                     │
│    - 混批 → 排除                               │
│ 3. 在剩余候选仓中，按排序方式排序               │
│ 4. 按分仓策略分配：                            │
│    - 优先整单同仓 → 找第一个能全满足的仓        │
│    - 不允许多仓 → 必须找到单仓满足全部SKU       │
│    - 允许多仓 → 每个SKU找最优仓                │
│    - 允许同商品多仓 → 同SKU可拆量              │
│ 5. 检查结果是否合法                            │
│    - 合法 → 进入出库拆分                       │
│    - 不合法 → 进入第二轮                       │
└───────────────────────────────────────────────┘
    │ 不合法
    ▼
┌───────────────────────────────────────────────┐
│ 第二轮（去掉软约束）                            │
│                                               │
│ 去掉"不允许混批"等软约束，重新跑一遍           │
│ 库存校验从硬约束降为软约束（允许无库存分配）     │
│                                               │
│ 若找到方案 → 进入出库拆分                      │
│ 若仍无方案 → 进入兜底                         │
└───────────────────────────────────────────────┘
    │ 仍无方案
    ▼
┌───────────────────────────────────────────────┐
│ 兜底策略                                       │
│                                               │
│ - 挂起等待补货（超时转人工）                    │
│ - 通知人工处理                                 │
│ - 按仓库优先级强推（忽略库存）                  │
│ - 取消订单                                     │
└───────────────────────────────────────────────┘
    │ 分仓成功
    ▼
┌───────────────────────────────────────────────┐
│ 出库拆分                                       │
│                                               │
│ 根据参数生成出库单：                           │
│ - 一单一商品 → 每SKU独立出库单                 │
│ - 样品不能单独出库 → 挂靠主品或拦截            │
│ - 危险品独立出库 → 危品单独一单                │
│ - 大件独立出库 → 大件单独一单                  │
│ - 超最大出库单数 → 合并                        │
│                                               │
│ 出库校验：                                     │
│ - 样品变成独立出库单？→ 拦截                   │
│ - 危品和普通品同单？→ 拦截                     │
│                                               │
│ 校验通过 → 下发                               │
│ 校验不通过：                                   │
│   - 允许部分下发 → 合法的先发，违规的挂起       │
│   - 不允许部分下发 → 整单挂起                  │
└───────────────────────────────────────────────┘
```

## 四、边界场景覆盖验证

下面用你的测试用例逐个验证引擎能否覆盖：

### A. 普通商品

| 场景 | 引擎行为 | 结果 |
|------|---------|------|
| 场景1：单品单仓足量 | 第一轮：按优先级排序→第一个仓有商品信息+有库存→命中 | ✅ 整单单仓 |
| 场景2：按最短距离命中 | 第一轮：按距离排序→最近仓有货→命中 | ✅ 整单单仓 |
| 场景3：数量大，不允许同商品多仓 | 第一轮：逐仓检查，无单仓满足30件→不合法；第二轮：去掉软约束仍无方案→兜底 | ✅ 分仓失败 |
| 场景4：数量大，允许同商品多仓 | 第一轮：上海18+杭州12=30→合法拆量 | ✅ 同商品多仓 |

### B. 普通商品+快消液体

| 场景 | 引擎行为 | 结果 |
|------|---------|------|
| 场景5：同仓满足，优先整单 | 优先整单同仓=是→杭州综合仓两者都有→命中；出库：一单一商品→拆2张 | ✅ 单仓+仓内拆单 |
| 场景6：无同仓，允许多仓 | 优先整单=是但无同仓→允许多仓→洗发水→快消仓，T恤→服饰仓 | ✅ 多仓履约 |
| 场景7：无同仓，不允许多仓 | 不允许多仓→无单仓满足→第二轮仍不满足→兜底 | ✅ 分仓失败 |

### C. 大件商品

| 场景 | 引擎行为 | 结果 |
|------|---------|------|
| 场景8：大件单独下单 | 大件必须大件仓(硬约束)→过滤后只剩大件仓→有货→命中 | ✅ 整单单仓 |
| 场景9：电视+T恤，允许拆仓 | 大件→大件仓；T恤→服饰仓；允许多仓→合法 | ✅ 多仓履约 |
| 场景10：电视+T恤，不允许拆仓 | 不允许多仓→无单仓同时有电视+T恤→失败 | ✅ 分仓失败 |
| 场景11：电视+洗发水，大件独立出库 | 多仓分配成功→出库拆分：大件独立出库→各自一张 | ✅ 多仓+大件独立 |

### D. 危险品

| 场景 | 引擎行为 | 结果 |
|------|---------|------|
| 场景12：危品单独下单 | 危品必须专仓(硬约束)→只有危化品仓进候选→有货→命中 | ✅ 整单单仓 |
| 场景13：危品+T恤，允许拆仓 | 危品→专仓；T恤→服饰仓；危品独立出库→各自一张 | ✅ 多仓+危品独立 |
| 场景14：危品不可与普通品同订单 | **这是订单层面的前置拦截，应在审单阶段处理，不属于分仓引擎范围** | ⚠️ 审单规则覆盖 |
| 场景15：危品库存不足，普通仓不能兜底 | 危品硬约束→普通仓排除→专仓库存不足→失败 | ✅ 分仓失败 |

### E. 效期商品

| 场景 | 引擎行为 | 结果 |
|------|---------|------|
| 场景16：FEFO先到期先出 | 效期仓有货→分配；批次选择按FEFO逻辑→锁定最早批次 | ✅ 单仓+FEFO |
| 场景17：临期不允许出库 | 临期阈值7天→批次20260627剩3天→排除→无可用批次→失败 | ✅ 分仓失败 |
| 场景18：效期品+洗发水，允许拆仓 | 牛奶→效期仓；洗发水→快消仓→多仓 | ✅ 多仓履约 |
| 场景19：效期品+洗发水，不允许拆仓 | 不允许多仓→无同仓→失败 | ✅ 分仓失败 |
| 场景20：同商品多仓+允许混批 | 两仓凑货→合法 | ✅ 同商品多仓 |
| 场景21：同商品多仓+不允许混批 | 不允许混批(软约束)→第一轮失败；第二轮去掉混批约束？取决于配置。若为硬约束→失败 | ✅ 可配置 |

### F. 样品

| 场景 | 引擎行为 | 结果 |
|------|---------|------|
| 场景22：样品单独下单 | 分仓可成功→但出库校验：样品独立出库单→拦截 | ✅ 分仓后拦截 |
| 场景23：样品+正装，一单一商品 | 分仓成功→出库拆分→样品变独立→违反规则→拦截或挂靠主品 | ✅ 出库校验拦截 |
| 场景24：样品+T恤，无同仓 | 样品分到独立仓→出库必然独立→违规；允许部分下发→T恤先发，样品挂起 | ✅ 部分下发 |

### G. 库存不足与部分下发

| 场景 | 引擎行为 | 结果 |
|------|---------|------|
| 场景25：部分有货，不允许部分下发 | T恤能分配，洗发水不能→不允许部分下发→整单失败 | ✅ 整单失败 |
| 场景26：部分有货，允许部分下发 | T恤分配下发；洗发水挂起 | ✅ 部分下发 |
| 场景27：电视有货T恤缺，允许部分 | 电视先发，T恤挂起 | ✅ 部分下发 |
| 场景28：危品有货T恤缺，不允许部分 | 整单失败 | ✅ 整单失败 |
| 场景29：危品有货T恤缺，允许部分 | 危品先发，T恤挂起 | ✅ 部分下发 |

### H. 高冲突混合

| 场景 | 引擎行为 | 结果 |
|------|---------|------|
| 场景30：电视+牛奶+样品，不允许部分 | 电视→大件仓✓；牛奶→效期仓✓；样品→独立出库违规→整单拦截 | ✅ 整单失败 |
| 场景31：电视+牛奶+样品，允许部分 | 电视+牛奶先发；样品挂起 | ✅ 部分下发 |
| 场景32：5品类混合全部有货 | 5仓各发→检查最大出库单数→若≤5→5张出库单；若>5→拦截或合并 | ✅ 多仓+多单 |

## 五、引擎覆盖不了的场景（需要其他模块配合）

| 场景 | 为什么引擎管不了 | 应该谁管 |
|------|-----------------|---------|
| 场景14：危品不可与普通品同订单 | 这是订单合规性校验，不是分仓问题 | 审单阶段规则 |
| 库存锁定竞争（高并发） | 分配后到实际出库之间库存被占 | 库存服务的乐观锁/预占机制 |
| 承运商不支持该商品类型 | 分仓成功但配送受限 | 承运商匹配阶段 |
| FEFO批次选择细节 | 分仓确定了仓，批次是WMS层面的 | WMS出库策略 |

### 设计要点

1. **开关+标签** — 每个约束是一个开关，旁边有 [硬约束/软约束] 标签
2. **分组清晰** — 4个卡片组：排序、约束、策略、出库、兜底
3. **互斥自动处理** — 不允许多仓时，"同商品多仓"自动灰掉
4. **每个开关有一句话解释** — 鼠标悬停或右侧灰字
5. **测试面板展示两轮执行过程** — 第一轮结果 → 第二轮结果 → 最终分配

## 九、总结

**核心设计原则：**

1. 引擎固定（两轮约束求解），用户配参数组
2. 每条规则 = 条件 + 参数组
3. 约束分硬/软，第二轮自动放宽软约束
4. 分仓和出库拆分是两个独立阶段，分仓成功不等于出库合法
5. 系统提供预设模板，降低上手成本
